# Project Instructions

## Git & GitHub Workflow

This project should be tracked in git and backed by a GitHub repository so its
history can be reviewed later if needed.

- If the project isn't already a git repository, initialize one.
- If there's no GitHub remote yet, create a GitHub repository for this project
  (confirm visibility — public/private — and org/account with the user first).
- Commit impactful changes as they're made — new features, fixes, meaningful
  refactors, config changes — not every trivial edit. Use clear, descriptive
  commit messages that explain *why* the change was made, not just what
  changed, so the history is useful for later review.
- Push commits to the GitHub remote regularly so it stays in sync with local
  history.
- Never force-push, rewrite history, or delete branches without explicit
  user approval.
